# Встановлення Core на іншому ПК

[English](desktop-installation.en.md).

Windows 10/11 x64: відкрийте `/downloads` на сайті, створіть особистий обліковий
запис або увійдіть, завантажте exe та відкрийте його. Кнопка «Встановити й
відкрити» копіює програму до `%LOCALAPPDATA%/Programs/Lokvetia Core` і додає
ярлик до меню «Пуск». Права адміністратора, Git та окремий Python не потрібні.
Це попередня версія без цифрового підпису видавця; SHA-256 опубліковано поруч.

Програма відкриває майстер першого запуску в браузері. Дані знаходяться в
`%LOCALAPPDATA%/Lokvetia/workspace`, окремо від виконуваного файла. Повторний
запуск відкриває вже запущену студію. Кнопка завершення роботи зупиняє локальний
HTTP-сервер. Студія слухає лише `127.0.0.1` і вимагає власну локальну сесію.

AI-провайдер і локальна модель підключаються через **Доступ до AI** у локальній студії; майстер автоматично встановлює потрібні інструменти, завантажує модель і перевіряє її готовність. Godot налаштовується окремо. Завантаження
Core не є підпискою на AI і не означає готовність повного автономного створення
гри. Пакети macOS/Linux та підписані автоматичні оновлення не включені.

## Оновлення на іншому ПК

Git push і оновлення сайту не змінюють уже встановлений EXE. Потрібно опублікувати новий перевірений пакет, після чого на кожному ПК завершити роботу студії, завантажити новий EXE й натиснути **Встановити й відкрити**. Видаляти студію, ігри або моделі перед цим не потрібно. Інсталятор замінює програму у її звичайній папці та зберігає попередній EXE; робочі дані й моделі залишаються окремо. Перед оновленням робочої бази збережіть її резервну копію. Якщо заміна файла заблокована, завершіть запущену студію й повторіть.

Для інсталяції з вихідного коду потрібні оновлення її checkout/пакета й перезапуск локального сервера. Саме перезавантаження вкладки не встановлює новий Python-код.

## Облікові записи

`LOKVETIA_PERSONAL_REGISTRATION=1` вмикає самостійну реєстрацію в identity service.
За замовчуванням лишаються запрошення. Особистий запис має власний непрозорий
ідентифікатор і доступ лише до свого профілю та завантажень. Він не вступає до
організації і не бачить спільних проєктів, ключів, звітів або керування студією.
Email використовується для входу; підтвердження володіння email і відновлення
пароля поштою ще не реалізовані. Чинне запрошення резервує адресу й не може
бути замінене самостійною реєстрацією. Підвищення прав лишається окремою дією.

## Пакування та публікація

У середовищі Windows із встановленим Core та залежностями web:

```powershell
python -m pip install pyinstaller==6.22.3
python scripts/build_desktop.py --out desktop-output
```

Пакет містить інтерпретатор, код і залежності, але не локальні дані, ключі,
профілі провайдерів або моделі. `desktop-release.json` містить розмір і SHA-256.
Збірка сама не позначає пакет перевіреним: потрібно встановити й запустити
саме цей exe в окремому порожньому каталозі та зберегти результат.

`LOKVETIA_DESKTOP_RELEASE_DIR` має вказувати на окремий каталог з маніфестом та
опублікованими файлами. Каталог монтується в контейнери лише для читання.
Маршрут завантаження допускає лише імена з маніфесту, перевіряє розмір і SHA-256
і вимагає вхід. Реєстрацію слід вмикати лише після оновлення identity, Core,
Lokiravia та gateway: кожна HTTP-межа має відхиляти доступ `account_user` до
операторських даних. Gateway вимагає окрему ознаку `workspace_access`.
