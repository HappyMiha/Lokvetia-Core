# Локальний наскрізний цикл платформера

[English](godot-prototype-cycle.md)

`lokvetia-prototype` створює простий Godot 2D платформер із текстової ідеї та
новий Windows EXE після текстової правки. Реальна локальна модель Ollama повертає
специфікацію, яку система перевіряє й перетворює на код через довірені шаблони.
Модель не передає виконуваний код або команди оболонки.

Підтримуються назва, швидкість руху (220–300), сила стрибка (520–560) та один або
два стрибки. Рівень має чотири фіксовані платформи, ціль, падіння й перезапуск.
Інші механіки мають повертатися як непідтримувані. Цей доказ не означає готовність
генерації довільних ігор або загального багаторольового виконавця Studio.
Сайт і графічний інтерфейс настільної програми поки не викликають цю команду.
Наявні дозволи лише на планування не розширюються.

## Дві версії

Потрібні Windows, Git, Python 3.11+, встановлений Core, уже завантажена модель
`qwen2.5-coder:7b` або `qwen2.5-coder:14b` в Ollama на `127.0.0.1:11434`,
підтримуваний консольний Godot і відповідні Windows export templates. Для
перевірки EXE з графікою потрібна активна настільна сесія. Команда не завантажує
моделі, не встановлює служби й не використовує платних провайдерів.

Прапорець `--execute-local` явно дозволяє один обмежений локальний запит до
моделі, створення знімка коду, локальний Git-коміт, збірку та тест EXE. Він
потрібний для кожного нового запиту. Без нього файли та запити до моделі не
створюються. Команда нічого не публікує й не пушить.

```powershell
$godotExe = 'C:\Tools\Godot\Godot_console.exe'
$gameRoot = Join-Path $PWD 'my-platformer'
python -m agent_factory.godot_prototype create --root $gameRoot --request 'Створи простий платформер Sky Steps зі звичайним стрибком і зеленою ціллю.' --command-id first --godot $godotExe --execute-local
$first = Get-Content (Join-Path $gameRoot 'revisions\first\result.json') -Raw | ConvertFrom-Json
& $first.artifact
python -m agent_factory.godot_prototype revise --root $gameRoot --request 'Додай подвійний стрибок.' --base-version $first.version --command-id double-jump --godot $godotExe --execute-local
$second = Get-Content (Join-Path $gameRoot 'revisions\double-jump\result.json') -Raw | ConvertFrom-Json
& $second.artifact
```

Встановлена команда `lokvetia-prototype` приймає ті самі аргументи. Стрілки
рухають гравця; Space або Enter виконує стрибок і перезапускає завершений раунд.
Перша платформа суцільна: підстрибніть біля неї та рухайтесь над нею поблизу
вершини стрибка. Ігрові дані вбудовані в EXE: гравцю не потрібні Godot, Python
або Ollama.

## Докази та збереження версій

Кожна правка має окремий каталог із вихідним запитом, базовою версією, точним
дайджестом моделі, відповіддю, перевіреною специфікацією, Git-комітом коду й
журналами збірки. Попередні EXE зберігаються. Локальні записи можуть містити
приватні запити користувача: їх не слід автоматично додавати в Git.

Godot імпортує проєкт, перевіряє всі скрипти, виконує тест без графіки та
експортує Windows x64. Потім саме експортований EXE запускається у вікні Windows.
Тест перевіряє рух, зіткнення з підлогою, звичайний і повторний стрибки, заборону
зайвого стрибка, приземлення, перемогу, падіння та перезапуск обох результатів.
Окремий маршрут проходить весь рівень від старту до цілі лише ігровими
натисканнями. Перевірки граничних умов цілі й падіння окремо переставляють
гравця; маршрут і перевірки стрибків цього не роблять.

`evidence/runtime.json` містить виміряні вертикальні швидкості й позиції маршруту;
`evidence/game.png` — кадр із запущеного EXE. Після запуску повторно перевіряється
хеш EXE. Лише успішна версія замінює поточну в наявному журналі playable versions.
Автоматична перевірка графіки не видається за ручне тестування людиною: для
останнього залишається явна прогалина доказів.

Повтор тієї самої успішної команди повертає її результат без нового запиту до
моделі. Змінений запит зі старим ID, застаріла базова версія, змінений EXE,
правка без змін, некоректні дані моделі або провалений тест відхиляються.
Після невдалого чи перерваного запуску докази залишаються; нова спроба потребує
нового ID. Переривання після зміни вказівника версії відновлюється без повторної
генерації чи збірки.

Запит до моделі обмежений 180 секундами, 384 токенами та відповіддю до 32 КіБ;
доступний лише фіксований loopback endpoint без проксі й перенаправлень.
Автоматичного платного резервного провайдера або необмежених повторів немає.
Операції Godot мають тайм-аути адаптера, тест EXE — 40 секунд. Блокування
локального проєкту не допускає конкурентних правок.

```powershell
python -m unittest tests.test_godot_prototype tests.test_godot_pack tests.test_godot_engine tests.test_playable_versions -q
```

Модульні тести використовують підставні інструменти й не є доказом реальної
збірки. Результати справжнього циклу двох EXE наведені в
[звіті перевірки](godot-prototype-proof.json).
